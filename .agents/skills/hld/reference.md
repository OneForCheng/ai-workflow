## 内容规范（评审导向）

### 必须包含

- 业务目标与方案边界
- 术语定义（消除评审歧义）
- 逻辑视图（模块/服务关系）
- 核心流程（Mermaid 图 + 简要说明）
- 接口变更清单（新增/修改/废弃分类）
- 数据变更清单（新增/修改/删除分类）
- 集成关系与外部依赖

### 禁止包含

- 具体代码、类定义、方法实现
- SQL DDL、详细字段类型定义（数据视图用业务语义描述字段即可）
- 具体框架配置、部署脚本
- 单元测试实现细节
- 过度展开的边缘流程与非核心异常

### 抽象性要求

- 接口：RESTful 语义 + 路径 + 方法 + 业务级入参/出参说明
- 数据：表名 + 业务含义 + 主要字段说明 + 实体关系
- 流程：业务步骤与系统间交互，非代码调用链
- 图表：Mermaid 优先，只画关键路径

## 确认语句速查

| 阶段 | 用户确认语句示例 |
|------|------------------|
| 1 → 2 | 「需求材料已提供完毕」「可以开始澄清」 |
| 2 → 3 | 「需求理解正确，可以开始方案设计」「确认需求，进入方案设计」 |
| 3 → 4 | 「方案确认，可以产出文档」「确认方案，生成文档」 |
| 4 完成 | 「文档确认」「可以进入详细设计/实现」 |

## 质量自检清单（产出前）

- [ ] 需求是否经用户**明确确认**后才进入方案设计？
- [ ] 方案是否经用户**明确确认**后才产出文档？
- [ ] 是否覆盖 In Scope，且 Out of Scope 未悄悄纳入？
- [ ] 接口/数据变更是否按 新增/修改/废弃（或 新增/修改/删除）分类？
- [ ] 是否标注现有可复用资产 vs 需新建项？
- [ ] 文档是否无实现细节（无代码、无 DDL）？
- [ ] 图表是否只保留关键路径？
- [ ] 是否附带待确认项与决策记录？
- [ ] 全程是否未擅自修改代码/配置？

## 特殊情况

### 无代码库 / Greenfield

- 阶段 2 侧重业务上下文、竞品、约束
- 逻辑视图与集成视图基于假设架构，标注待选型项

### 纯流程/运营类需求

- 接口设计、数据视图可标注 N/A
- 强化流程设计与集成视图中的人工/系统协作

### 小改动 / Hotfix

- 可压缩阶段 1，但仍须确认范围与验收标准
- 方案聚焦最小变更面，避免过度文档化

### 用户在本流程中要求写代码

- 暂停并确认：「是否结束高阶方案流程并进入实现？」
- 得到明确肯定后，建议切换 `/rdd`；本规则不再约束实现阶段
