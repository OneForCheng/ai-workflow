# quick 档（小改动最小闭环）

入口：`/flow quick <需求>`。目标：**3 轮内完成**（确认 → 实现 + checklist → 收尾），只落 1 个 Plan + 1 条索引。

quick 压缩的是**Feature 与确认轮次**，不是审查与质量门。

## 1. 适用判定（语义优先，文件数辅助）

先问「这次改动的语义是什么」，再看文件数：

| 语义 | 档 |
|------|-----|
| 修补、文案、样式、小优化、既有行为对齐 | **quick** |
| 新功能、新契约、新业务规则 | standard（必须新建 Feature） |
| 重构、跨模块、换实现方式 | standard |
| 无人值守 / 任务多 | run |

| 辅助条件 | 判定 |
|----------|------|
| 文件数 ≤5 且单模块 | 可 quick |
| >5 文件或跨模块 | standard |
| 碰契约 / 表结构 / 权限 / 迁移 / 新依赖 | standard |
| 命中高风险路径（见 `review.md`） | 仍 quick，但 Review 强制 checklist |

**兜底**：用户不认可你的判档时，一句「走 standard」立即改档，不讨论。

## 2. 三条护栏（复用 Feature 时）

1. **不碰正文**：只产出 Plan；Feature 的 `status`、AC、业务规则一律不动。
2. **只许追加关联**：Go 阶段对复用 Feature 的唯一动作是 `## 关联` 加一行 `修补：PLAN-…`；不勾 AC、不改 status。
3. **改需求即升档**：需要动 AC / 范围 / 业务规则的，不属于 quick → 升 standard 并新建 Feature。

> `frozen` 哈希只覆盖「目标 / 范围 / 业务规则 / 验收标准」，`## 关联` 不在其中，所以追加关联是安全的。

## 3. 定位复用 Feature（不破坏读集）

只允许三条路径，命中即停：

1. **用户点名**（「归到 FEAT-003」）
2. 读 `docs/features/README.md`，按 `scope` 命中 **1 篇**
3. 从上一个 Plan 的 `## 关联` 顺藤摸瓜

- 最多查看 **2 篇**；仍不确定就问「归到哪个 Feature，还是新建最小 Feature」
- **禁止** grep / 全量扫描 `docs/features`
- 无归属时新建最小 Feature：目标一句 + 一条 AC

## 4. 一次确认（G0 + G1 合并）

输出一屏，然后停止：

```markdown
## quick 确认

- 重量：quick（理由：语义=修补；2 文件；单模块）
- 歧义：无 ｜ `<词>` 按 `<解释>` 理解，如不对请指出
- 归属：FEAT-003（复用，不改正文）｜新建 FEAT-004
- 改动：`src/refund/List.tsx:88` — 空状态文案
- 验证：`pnpm test refund`
- 回填：无 ｜ designs `api/refund.md`
- 风险：无 / <一句>
- Review：checklist（命中高风险时说明）

确认后我开始实现。
```

不确定的假设必须写进「歧义」行，不允许藏进实现；没有歧义也要写「无」。

**确认前禁止**改代码、建文件、装依赖、跑迁移。

## 5. 执行（3 轮内）

1. **确认**：用户回复确认
2. **落档 + 实现**：写 `PLAN-<YYYYMMDD>-<slug>.md`（`tier: quick`，一页）+ 索引 → 实现 → 跑 `fast` 门禁
3. **收尾**：回填事实（仅当事实变化）→ Plan §8 精简（含 `变更总结` + type）→ Review checklist → Compound（有摩擦才写）→ G2 一行回溯 → **变更总结 + 询问提交**（见 `reference/summary.md`）

Plan 至少包含：需求一句话 / 改动清单 / 验证 / 回填项（可无）/ 风险。矩阵与 AC 覆盖可省略。

## 6. 越界处理

实施中发现下列任一情况，**立即停**：

- 改动超过 5 个文件或跨模块
- 需要改契约 / 表结构 / 权限 / 迁移 / 新依赖
- 发现语义其实是新需求（要改 AC / 范围 / 业务规则）

动作：说明原因 → 升 standard → 补 Feature / Plan 相应段落（已改内容保留）→ 重新确认后继续。**不偷偷扩范围。**

## 7. 与 `/do` 的边界

| | `/do` | `/flow quick` |
|---|--------|----------------|
| 文档 | 不维护 `docs/` | 写 1 个 Plan + 索引 |
| 适用 | 一次性 / 实验 / 脚本 | 属于项目、以后要查 |
| 追溯 | 对话 | 可回溯到 Feature |

## 8. 禁止

- 跳过确认先改代码
- 改复用 Feature 的正文或勾 AC
- 用 quick 承载重构 / 跨模块 / 契约变更
- 跳过质量门
- 默认 skip Review（quick 与 standard 同样默认 checklist）
- 未确认先执行 commit（提交统一走 `reference/summary.md`）
- 为找归属扫描全库
