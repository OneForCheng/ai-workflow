# Compound 模式（系统进化）

前置：Review 已结束（含 `skip`）且 **G1.5** 已通过。

目标：把本轮可复用的洞察**编码回系统**，使下一轮更容易——不只回填业务事实（那是 Go 的职责），还包括规则、决策、上下文与**工程/验证效率**。

> Compound Engineering 要点：代码不是唯一产物；产生代码的系统才是。无洞察时诚实跳过，禁止空转改文件。  
> **但**：「只写 Plan `流程改进` / 只建议 AGENTS 补丁、不改业务 docs」**不算空转**，也**不得**写成「无系统级沉淀」。

## 读集（硬约束）

**允许**：当前 Plan（含 **§8 偏差段**、Review 结果）、本轮已改动的事实文档**路径列表**、必要时打开其中 0–1 篇核对「是否已有重复 standard」。

**必须先扫**：§8 的 `工程摩擦（候选 Compound）`、`验证`、`遗留`——非「无」的条目默认进入下方洞察判定（尤其问题 5），禁止视而不见。

**禁止**：为找灵感全库扫描；重跑 Go 的实现步骤；未经用户同意大幅重写 `AGENTS.md`。

## 洞察判定

先自问（不对用户逐条朗读，内部判定即可）：

1. 是否出现可复用的通用约定（未来其他模块也会踩）？
2. 是否有值得归档的一次性架构/技术决策？
3. 项目 `AGENTS.md` 是否缺一条能防止同类失误的短规则？
4. 是否值得沉淀为**可安装 skill**（重复流程、检查清单、领域套路）？
5. 是否发现读集 / **质量命令** / 验收可验证性上的效率改进？——**含** Go 偏差段已记账的工程摩擦

### 问题 5 的显式信号（命中任一条 → 本轮不得判「无洞察」）

| 信号 | 典型例子 | 最低落点 |
|------|----------|----------|
| 假失败 / 门槛误伤 | 单文件 `vitest` 触发**全仓** coverage 门槛；与改动无关的 lint 全量噪音被当成门禁 | `流程改进`；若缺「局部验证」说明 → **建议** `AGENTS.md` 补丁（优先级 3） |
| 降级验收绕过 | 关 `--coverage`、跳过某步、手写非文档化命令才通过 | 同上 |
| 命令/读集低效 | 只能全量 `verify`、缺 `type-check:file` / 单测路径约定 | `流程改进`；可固化则升 1 或 3 |
| 重复踩坑 | 本轮或对话中同一摩擦出现 ≥2 次 | 优先升到 AGENTS / standard |

**全否**（且 §8 工程摩擦为「无」）→ 对话写「Compound：无系统级沉淀」→ 追加 Plan 段 → 输出 **G2**，结束。

**有一或多条** → 按下方落点表处理，**本轮默认最多落档 1–2 处**（对话中的 skill 草稿与「仅建议、待用户确认的 AGENTS diff」不计强制落档次数，但仍只出一份主建议）。

> **语义澄清**：有洞察但本轮只写入 Plan「流程改进」、或只给出 AGENTS 建议 diff 而未改文件 → 对话与 Plan 写「有洞察（流程/工程）」；**禁止**用「无系统级沉淀」概括。

## 落点优先级（择优，勿摊大饼）

| 优先级 | 落点 | 何时 | 写规则 |
|--------|------|------|--------|
| 1 | `docs/standards/*.md` | 与具体需求无关、可判定违反（MUST / MUST NOT） | **变更**最终态；禁止重复已有 standard |
| 2 | `docs/others/adr/*.md` | 一次性决策、备选与被否理由 | **追加**新 ADR |
| 3 | 项目根 / 子项目 `AGENTS.md` | 短规则即可防再犯（**含**质量命令怎么跑局部验证） | **建议 diff**；大段重写须用户确认；只追加/补丁，不整体替换（除非用户要求） |
| 4 | **对话内 skill 草稿** | 重复流程值得技能化 | **仅对话输出**完整 `SKILL.md` 草稿（含 front-matter）；**不写入仓库、不执行安装**；询问用户是否转化为项目或全局 skill |
| 5 | 效率 / 可验证性 / **工程摩擦** | 读集可再缩、缺检查命令、验收假失败、工具链 UX | **必须**写入 Plan `## Compound` 的「流程改进」；若属项目工程约定 → **同时**按优先级 3 给出 AGENTS 建议（可一句询问是否写入） |

**禁止**：把业务最终态再抄进 Compound（设计/接口事实属于 Go 回填）；为 Compound 新建与需求绑定的「假 standard」；自动 `npx skills add` 或写入 `.agents/skills/`；因「禁止空转」而抹掉已发现的流程改进。

## Skill 草稿（仅对话）

若触发优先级 4，在对话中输出：

```markdown
### Skill 草稿（未写入仓库）

建议 name: <slug>
建议 scope: 项目 skill / 全局 skill（请用户选）

---
name: <slug>
description: >-
  <英文：做什么 + 何时用>
disable-model-invocation: true
---

# <标题>
…
```

然后明确问：

> 以上草稿**尚未写入任何目录**。若要落地，请告知：写入当前项目 `.agents/skills/`、安装到全局，或放弃。

未获明确指示前，**不创建** skill 文件。

## Plan 追加（必做）

无论有无落档，在 Plan 文末**追加**（不回改上文）：

```markdown
## Compound
- 洞察：无 / <一句话；若来自 §8 工程摩擦请点名>
- 落点：
  - standards：无 / `STD-…` — <改了什么>
  - adr：无 / `ADR-…`
  - AGENTS：无 / 已建议补丁（待用户确认）/ 已写入
  - skill 草稿：无 / 已在对话给出 `<name>`（未安装）
  - 流程改进：无 / <下次如何更省 token、更可验证，或工具链该怎么改>
```
