# Review 模式（可选·轻量）

前置：Go 已完成实现、质量检查、事实回填、索引同步与 Plan 偏差段追加。

目标：用**固定短清单**做一轮可扫描的自检，拦住明显问题后再 Compound。不为「深度审查」堆上下文。

## 策略判定

读取当前 Plan 的 **§7 Review 策略**（或 front-matter / 文内等价声明）：

| 取值 | 行为 |
|------|------|
| `skip`（**默认**；未声明视同 skip） | 输出一行「Review：跳过」→ 直接加载 `compound.md` |
| `checklist` | 执行下方 checklist → 通过 **G1.5** 后再进 Compound |

**禁止**：启动多 agent；通读全库；重新打开无关 Feature / 历史 Plan；把 Review 写成大段散文。

## 读集（硬约束）

**允许**：

1. 当前 Plan（§3 改动清单、§5 验收、§7 偏差）
2. 本轮实际改动的文件路径列表（来自偏差段或已知编辑集；可用 `git diff` / `git status` **仅限本轮范围**）
3. 仅当某条 checklist 需要核对契约时，打开 Plan §6 中**已回填**的那 0–2 个 design/standard 文件

**禁止**：全量扫描或 grep `docs/`；读未在本轮改动的大文件全文「碰运气」。

## Checklist（固定 4 条，勿增删）

对每条给出：`通过` / `风险` / `不适用`，风险须附**具体文件或符号**与一句理由。

| # | 视角 | 问什么 |
|---|------|--------|
| R1 | 正确性 | 是否覆盖 Plan §5 验收；偏差是否已声明 |
| R2 | 边界与失败 | 空值、权限、幂等、错误路径是否遗漏明显坑 |
| R3 | 安全 | 注入、密钥/PII 落日志、越权；无则标不适用 |
| R4 | 可维护 | 是否超出 Plan 范围的无关重构；命名/分层是否与项目既有模式冲突 |

## 产出格式（对话，单轮）

```
## Review（checklist）

| ID | 结果 | 说明 |
|----|------|------|
| R1 | 通过 / 风险 / 不适用 | … |
| R2 | … | … |
| R3 | … | … |
| R4 | … | … |

### P1（须处理）
- [ ] …  或写「无」

### P2（可选）
- [ ] …  或写「无」
```

## G1.5 交互

- 存在 **P1** → **停止**：先修复代码（必要时回补 designs）并更新 Plan §7 偏差，或请用户明确「接受风险，继续 Compound」
- 无 P1 → 将下列摘要**追加**到 Plan 文末（不回改上文），然后加载 `reference/compound.md`：

```markdown
## Review 结果
- 策略：checklist
- P1：无 / <已修复或已接受的摘要>
- P2：无 / <留作后续>
```

`skip` 时追加：

```markdown
## Review 结果
- 策略：skip
```
